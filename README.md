# KegTrace · 精酿酒吧空桶回收押金与批次追溯平台

## 原始需求

> 建设精酿酒吧空桶回收押金与批次追溯平台，可采用 React、Go 和 PostgreSQL。酒厂向合作酒吧发出不同批次的 IPA、世涛、小麦和酸啤时，平台记录酒桶编号、容量、酒液批次、灌装日期、最佳饮用期、押金金额、配送司机和酒吧收货人。酒吧开桶后可以反馈出酒速度、气压问题、口味异常和客诉；酒桶打空后，酒吧预约回收，司机扫码确认空桶数量、外观、残液和封盖状态。若酒吧延迟归还、酒桶丢失、桶体变形、批次口味被多家投诉、司机漏扫或清洗厂检测不合格，平台要把酒厂仓库、酒吧店长、司机、清洗厂、品控和财务放在同一只桶或同一批酒中处理。押金释放、扣款、再灌装资格和批次停售建议都基于这些记录生成。平台还要支持多城市经销商、酒桶押金账期、节日临时铺货和批次召回通知。酒厂需要按桶看到它在哪家酒吧、是否开桶、是否回收、是否清洗合格，财务需要按桶释放或扣减押金。批次召回时还要区分已售卖、已开桶和未开桶库存。如果某个批次暂停销售，平台还要通知已收货酒吧、待配送订单和经销商库存，避免继续开桶售卖。

### 本期新增：口味异常批次排查

多家酒吧反馈同一批 IPA 有氧化味时，平台自动建立**批次排查单**并在一张证据链中关联：灌装时间、运输温度（司机送达时录入，>8℃ 自动标超温并通知品控）、酒吧开桶日期、出酒设备（板式扎啤机/酒柱等）与客诉照片（店长可直接上传）。品控确认前，该批次剩余酒桶进入**暂停配送**状态：在库桶禁止出库、待配送/配送中订单自动暂缓、在店桶禁止开桶，并通知持桶酒吧与经销商。暂停期间，**销售人员**可查看受影响酒吧与同酒款在售、有现货的**可替换批次**。品控结论三选一：

- **确认召回**：已售卖/已开桶/未开桶三类库存拆分，按受影响酒吧自动生成换货备货任务；销售确认替换批次，仓库推进备货并通知酒吧；召回决定同步销售、仓库、财务、酒吧与经销商。
- **已开桶折价**：按已开桶生成折价补偿台账（财务结算），批次解除暂停、恢复配送。
- **排除批次问题**：解除暂停，暂缓订单恢复待配送。

## 技术栈与架构

- **前端**：React 18 + Vite + React Router（构建产物由 Go 服务静态托管，单端口交付）
- **后端**：Go 1.22（标准库 `net/http` + `lib/pq`），REST API，Bearer Token 会话，逐接口角色鉴权
- **数据库**：PostgreSQL 16（仅 compose 内部网络，不发布宿主端口）
- **部署**：多阶段 Dockerfile（非 root 用户 + HEALTHCHECK），`docker compose` 一键启动
- **文件**：客诉照片经 `POST /api/uploads` 上传，存于 `UPLOAD_DIR`（容器内 `/app/data/uploads`，已预置演示照片），由 `/uploads/*` 静态托管；演示用途存本地磁盘，生产应换对象存储。

```
┌────────────┐      ┌─────────────────────┐      ┌────────────┐
│  浏览器     │ ───▶ │  app (Go + React)   │ ───▶ │  postgres  │
│            │ :8080│  /api/* + 静态站点   │ 5432 │  (内部网络) │
└────────────┘      └─────────────────────┘      └────────────┘
```

## 快速启动（验证方式 = 宿主 docker compose up）

```bash
cp .env.example .env        # 按需修改 CC_PUBLISH_PORT 等
docker compose up -d --build
docker compose ps           # app 健康检查通过后
docker compose port app 8080   # 查看实际映射端口（如 0.0.0.0:3222）
# 浏览器访问 http://localhost:<端口>
# 结束验证后释放资源：
docker compose down
```

- 应用容器内部固定监听 `8080`，仅应用端口通过 `${CC_PUBLISH_PORT}` 发布到宿主；数据库不发布端口，应用通过服务名 `db` 访问。
- 首次启动自动建表并写入演示数据（批次 / 酒桶 / 在途配送单 / 投诉工单 / 押金流水 / 口味异常排查单等）。

## 本地开发


## 演示数据与关键业务流

种子数据包含：3 个城市经销商、4 家酒吧、6 个批次（IPA/世涛/小麦/酸啤 + 7 月老批次 + 可替换的新 IPA）、25 只酒桶（在库/配送中/在店/已开桶/已打空/待清洗/待再灌装/清洗不合格各状态）、已签收/配送中/节日铺货/排查暂缓配送单各一、**批次 IPA-20260901 已被北京、上海 2 家酒吧投诉氧化味（排查单 INV000001，批次处于"排查暂停配送"，证据含 11.8℃ 超温运输记录与客诉照片）**、酸啤批次已被 2 家酒吧投诉（已生成品控工单）、1 只逾期 54 天未归还酒桶、1 笔待释放押金。

推荐体验路径：

1. **仓库** `warehouse`：批次管理新建批次 → 酒桶追溯登记酒桶 → 配送订单新建配送单（勾选在库酒桶，可选"节日临时铺货"）。
2. **司机** `driver1`：配送订单"开始配送 → 送达（录入运输温度，填 10℃ 以上会标超温并通知品控）"。
3. **店长** `bar1`：配送订单"签收"（填收货人，自动按桶收取押金）→ 酒吧操作台"开桶 → 反馈（勾选口味异常+客诉，选择口味现象、出酒设备并上传客诉照片）→ 打空" → 勾选空桶"预约回收"。
4. **多家投诉自动排查**：`bar1`、`bar2` 分别对同一在售批次提交口味异常反馈（种子中 IPA-20260901 已满足）→ 自动生成"批次口味投诉"工单**并建立排查单、批次进入暂停配送**（在库禁出库、订单暂缓、禁开桶），通知品控/仓库/销售/持桶酒吧/经销商。
5. **销售** `sales1`：批次排查 → 打开 INV000001，查看证据链（灌装时间/运输温度/开桶日期/设备/照片）、受影响酒吧、可替换批次（IPA-20260920 在库 4 桶）。
6. **品控** `qc`：在排查单底部出具结论：
   - 选"确认召回"→ 库存按已售卖/已开桶/未开桶拆分，按受影响酒吧生成换货备货任务并通知各方；
   - 或选"已开桶折价 X%"→ 已开桶生成折价补偿（财务可结算），批次恢复配送；
   - 或选"排除批次问题"→ 解除暂停、暂缓订单恢复。
7. **销售 → 仓库换货闭环**：`sales1` 在备货任务上"确认替换批次（IPA-20260920）与桶数"→ `warehouse`"开始备货 → 备货完成"（完成前必须已确认替换批次；完成后通知酒吧与销售）。
8. **司机** `driver1`：回收预约 → 详情逐只扫码（外观/残液/封盖）→ 完成回收；少扫会生成"司机漏扫"工单；外观选"变形/破损"自动生成桶体异常工单并取消再灌装资格。
9. **清洗厂** `washer`：清洗检测登记。合格 → 酒桶"待再灌装"且自动生成"押金待释放"（通知财务）；不合格 → 生成工单、取消再灌装资格。
10. **财务** `finance`：押金台账按账期查看收取/释放/扣减/折价补偿，对待结算记录点"结算"；酒桶详情页可直接"押金扣减"；可手动"扫描逾期未归还"。
11. **品控** `qc`：批次详情亦可直接"暂停销售"/"发起召回"（召回返回已售卖/已开桶/未开桶三类拆分，并自动关闭该批次进行中的排查单）。
12. **协同工单**：六类异常（延迟归还/丢失/变形/批次投诉/漏扫/清洗不合格）在同一工单中留言协同，仓库/品控/财务可结案并附带押金扣款。

## 说明

- 密码使用加盐 SHA-256 哈希（演示用途；生产应替换为 bcrypt/argon2）。
- 会话保存在应用内存中，重启后需重新登录。
- 逾期判定：酒桶到店超过 30 天未归还（服务启动、回收完成、手动扫描时触发检查）。
- 运输冷链建议温度上限 8℃：超过则在排查证据链中标红，并在送达时通知品控（阈值见后端 `transportTempLimit`）。
